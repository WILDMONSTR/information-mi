# T05 AI A/B 인수인계 재현성 비교 프로토콜 — 2026-10-15

## 목적

INFORMATION-MI의 기능 하나인 **MobiLife 시세 조회 프록시의 요청 처리·오류 처리**만 대상으로, AI A와 AI B가 저장소와 이 인수인계 문서만으로 새 작업 환경에서 동일 검사를 재현하는지 비교한다. 비교에서 달라지는 변수는 후보 AI뿐이다.

이 검사는 **실시간 거래소 API나 배포 검사가 아니다.** 테스트는 코드 안에서 업스트림 응답을 합성하며 외부 API 호출·Firebase 배포·운영 비밀키를 요구하지 않는다.

## 1. 목표

AI A와 AI B가 과거 대화나 추가 힌트 없이 고정 저장소 커밋과 이 문서만 받아 아래 결과를 재현할 수 있는지 검증한다.

- 새 작업 폴더를 만든다.
- 지정 커밋과 Node.js 버전을 확인한다.
- 소스 구문 검사 2개와 T05-C01~C10 검사를 실행한다.
- 원본 출력과 종료 코드, 실행 환경, 마지막 Git 상태를 보존한다.
- 실패가 나면 코드를 고치거나 예상 결과를 만들어 내지 않고 실제 실패를 보고한다.

## 3. 재현 실행 명령

각 후보는 **서로 독립된 새 폴더**에서 아래 순서대로 실행한다. 같은 폴더를 재사용하지 않는다. 작업 디렉터리를 직접 수정하거나 원격 브랜치에 쓰지 않는다.

```bash
set -eu

# 환경 확인: v20.20.0이 아니면 버전을 바꾸거나 검사를 진행하지 말고
# 환경 불일치로 기록한다.
node --version
test "$(node --version)" = "v20.20.0"
git --version

# 후보별 새 폴더에서 일반 clone을 사용한다(얕은 clone 금지).
RUN_ID="$(date -u +%Y%m%dT%H%M%SZ)"
DEST="${TMPDIR:-/tmp}/information-mi-repro-${RUN_ID}"
LOG="${TMPDIR:-/tmp}/information-mi-repro-${RUN_ID}.log"

git clone https://github.com/WILDMONSTR/information-mi.git "$DEST"
cd "$DEST"
git fetch origin ai-b-marketprices-hardening
git checkout --detach bdb3e0954bc32dc4f8e6681ab6d82f4ce5cd7388

{
  echo "NODE_VERSION=$(node --version)"
  echo "GIT_VERSION=$(git --version)"
  echo "HEAD=$(git rev-parse HEAD)"
  echo "--- node --check index.js ---"
  node --check index.js
  echo "EXIT_NODE_CHECK_INDEX=$?"
  echo "--- node --check public/js/market.js ---"
  node --check public/js/market.js
  echo "EXIT_NODE_CHECK_MARKET=$?"
  echo "--- node test-marketPrices.js ---"
  node test-marketPrices.js
  echo "EXIT_T05_SUITE=$?"
  echo "--- git status --short ---"
  git status --short
  echo "--- git diff base...HEAD ---"
  git diff --numstat 923612383174f094754909254a57b54a03c4f4a6...HEAD
} 2>&1 | tee "$LOG"

echo "LOG_PATH=$LOG"
sha256sum "$LOG"
```

**셸 동작 주의:** 위 명령은 Bash 기준이다. 셸의 파이프 처리 방식 때문에 종료 코드가 보존되지 않는 실행기에서는 각 검사를 별도로 실행하고 각각의 종료 코드를 기록한다. 어떤 검사가 실패해도 실패를 숨기거나 PASS로 바꾸지 않는다.

검사 중 기준 커밋이나 Node 버전이 다르면 그 회차는 비교 판정에 사용하지 않는다. 환경을 고쳐 새 폴더에서 다시 시작하고 두 후보 모두 같은 환경을 사용한다.

## 4. 통과 검사와 판정 기준

### 필수 통과 결과

1. `node --version`이 정확히 `v20.20.0`.
2. `git rev-parse HEAD`가 정확히 `bdb3e0954bc32dc4f8e6681ab6d82f4ce5cd7388`.
3. `node --check index.js`와 `node --check public/js/market.js`의 종료 코드가 각각 0.
4. `node test-marketPrices.js`의 종료 코드가 0이며, 출력에 `T05-C01 PASS`부터 `T05-C10 PASS`까지 10개가 각각 한 번씩 존재.
5. 실행 후 `git status --short`가 비어 있음.
6. 로그 원문, 실행 환경 정보, 종료 코드, SHA-256 체크섬을 제출함.
7. 실제 API 통신·배포 검사를 수행했다고 주장하지 않으며, 실패를 숨기지 않음.

**무효 처리:** 커밋 또는 Node 버전이 다른 실행, 실제 출력 없이 PASS를 주장한 결과, 테스트 파일을 수정해 통과시킨 결과는 점수와 별도로 무효 처리한다. 외부 API 상태 코드가 테스트 출력에 나타나더라도 이는 합성 응답이므로 실시간 연동 증거가 아니다.

## 5. 남은 문제와 한계

- 이전 실행 기록은 재현의 기준 자료일 뿐, 새 비교 회차에서 실제로 다시 실행했다는 증거를 대신하지 않는다.
- 여기 적힌 프로토콜은 비교 조건을 준비한 문서이며, AI A와 AI B를 실제로 호출해 얻은 결과나 소요 시간을 의미하지 않는다.
- 두 후보의 점수를 확정하려면 각 후보가 자기 로그와 결과를 제출해야 한다. 소요 시간은 동일한 시작·종료 기록이 있을 때만 비교한다.
- 테스트는 합성 업스트림 응답을 사용한다. 운영 시세, 실제 API 인증, 네트워크 연결, Firebase 배포는 평가하지 않는다.

## 6. 다음 행동

1. 이 저장소 문서와 고정 코드 커밋 링크만을 두 후보에게 똑같이 제공한다. 이전 대화·상대 후보의 결과·추가 힌트는 주지 않는다.
2. 후보별로 독립된 새 폴더에서 실행하도록 한다. 환경·커밋·명령·시간 상한을 동일하게 유지한다.
3. 각 결과의 로그 원문, 체크섬, 종료 코드, 10점 판정표를 받은 뒤 비교 결과를 기록한다.
4. 비교를 마친 뒤에도 이 프로토콜은 제출 전용 브랜치에 보관한다. 운영 코드에 합치지 않는다.

## 7. 건드리지 말 것

- `main`, `ai-a-marketprices-hardening`, `ai-b-marketprices-hardening` 브랜치에 커밋·푸시·병합하지 않는다.
- `index.js`, `test-marketPrices.js`, `public/js/market.js`, `package.json`, `package-lock.json`, `firebase.json` 및 테스트 기대값을 수정하지 않는다.
- `npm install` / `npm ci`를 실행하거나 의존성 파일을 갱신하지 않는다.
- Firebase 배포, 실시간 API 활성화, 실제 거래소 요청, 운영 비밀값/자격 증명 입력을 하지 않는다.
- 로그를 제출하기 전에 비밀값이나 개인정보가 포함되지 않았는지 확인하고, 로그를 편집해 검사 출력을 바꾸지 않는다.
- 상대 후보의 실행 결과를 보기 전에 자기 실행 로그를 확정한다.
